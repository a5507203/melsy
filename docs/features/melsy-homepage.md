# Melsy 官网 V2 Feature Spec

## 1. Concept Brief 来源

本规格来自 `PRODUCT.md`、用户确认的 V2 信息架构，以及 `C:/Users/Admin/Downloads/7月墨悉官网v2/` 中的首页、产品、场景、合作、公司与研究材料。

- 当前阶段：需求已确认，进入实现。
- 目标用户：低空安全/园区/企业决策者为主；科研合作、产业伙伴、投资媒体与技术人才为辅。
- 核心问题：旧站以产品展示为中心，无法先建立“协同世界模型”的品类认知，也没有形成技术—产品—应用—证据—联系的完整说服链。
- MVP：中文响应式静态前端；一个核心首页和一个 About 二级内容页；本地图片与网页优化视频；联系区提供字段完整、前后端双重校验的合作需求表单，通过专用 Cloudflare Worker 与 Resend 将需求发送至墨悉团队邮箱，并保留扫码联系入口。
- 非目标：CMS、数据库、账号、在线购买、营销邮件自动化、附件上传或完整英文站。
- 关键假设：`contact@melsyai.com` 是可收信的团队邮箱；`mail.melsyai.com` 已在 Resend 验证；Worker 生产变量与 Secret 由运维配置并保持有效。上线验收通过真实测试邮件验证前两项。
- 待确认问题：后续是否增加适用于中国大陆访客的验证码；当前 MVP 使用蜜罐、平台限流和 Resend 幂等键控制滥用与重复发送，不以验证码作为首发阻塞项。

## 2. 统一语言

| 术语 | 定义 | 使用约束 |
|---|---|---|
| 协同世界模型 | 在共享状态、资源约束和因果演化下，为异构智能体生成协调决策与动作的技术范式 | 不等同于“多个智能体并行运行” |
| 空间训练场 | 面向低空空间任务的仿真、训练与验证环境 | 页面角色为 Train / 训练 |
| COS 协同操作系统 | 连接世界模型与多智能体执行，完成感知融合、任务编排与实时调度 | 页面角色为 Decide / 决策与调度 |
| 碎蜂 | 面向低空安全任务的硬件执行与验证系统 | 页面角色为 Execute / 执行；不展示未经批准的性能指标 |
| 低空产业核心落地 | 协同世界模型当前的商业切入场景 | 不代表公司长期能力只限于低空安全 |
| 产业合作 | 文档明确记录的联合研发、测试验证或行业协作 | 不把素材库中的 Logo 自动解释为客户关系 |

禁用或待审批口径：全球首个、世界级、90+%、300km/h、精准制导，以及仅存在于融资 PPT 的估值、收入、竞品与路线图内容。

## 4. 用户流程

### 主流程

1. 访客打开首页，在首屏理解协同世界模型与墨悉定位。
2. 继续阅读范式演进和核心机制，理解它区别于单智能体/并行多智能体。
3. 通过空间训练场、COS、碎蜂理解训练—决策—执行闭环。
4. 浏览四类应用和产业合作，判断相关性与可信度。
5. 点击“商务合作”，到达联系区；可扫码联系，或填写字段一致的合作需求表单。
6. 填写过程中，可见字段与当前 `submissionId` 保存于当前标签页会话；刷新页面后自动恢复，隐藏蜜罐不进入草稿。
7. 提交时先完成客户端必填项、邮箱和网址格式校验；校验通过后，页面进入提交中状态并向 Worker 发送固定 JSON 契约。
8. Worker 再次校验请求并调用 Resend；Resend 接受后页面显示“合作需求已提交”，清空草稿，团队邮箱收到包含全部字段的邮件并可直接回复访客工作邮箱。

### 替代流程

- 从导航直接进入产品、应用或产业合作锚点。
- 从首页进入 About，阅读后通过全站导航回到首页或联系入口。
- 从论文/研究条目打开已提供的外部论文链接。

### 异常与恢复流程

- 视频加载/播放失败：显示 poster 与完整文字说明，并允许继续浏览。
- JavaScript 不可用：核心内容、页面链接与锚点仍可阅读和导航。
- 减弱动态：停用自动播放与装饰动画，不影响信息结构。
- 表单字段不完整或格式错误：标记无效字段、聚焦第一个无效字段，并在状态区提示检查必填项、邮箱和网址格式。
- 同一标签页刷新：恢复此前填写的可见字段及其 `submissionId`；浏览器会话存储不可用时保持表单可填写和可提交，不阻断核心流程。
- Worker 拒绝字段或请求过于频繁：页面显示可恢复的校验/稍后重试提示并保留草稿。
- 网络、Worker 或 Resend 失败：页面显示通用失败提示，保留草稿并引导用户扫码联系；不得展示上游错误或密钥信息。
- 重复点击：首次提交完成前忽略后续提交；同一草稿失败重试复用 `submissionId`，由 Resend 幂等处理避免重复邮件。

## 5. 领域模型影响

本项目仍无服务端数据库、schema 或迁移；浏览器仅在当前标签页会话中保存联系表单草稿，Cloudflare Worker API 仍不持久化请求内容。

内容实体包括：页面、页面区块、产品、应用场景、合作案例、公司动态、联系入口和合作需求。HTML 是公开内容投影；合作需求从浏览器传至 Worker，再由 Resend 发送至团队邮箱，站点与 Worker 不建立额外数据库副本；本地媒体文件是展示资源；Markdown 规格与源文档是内容权威来源。

### API 契约

- `POST /contact`：仅接受 `application/json`。请求包含 `submissionId`、九个表单字段和隐藏蜜罐字段 `fax`。
- `OPTIONS /contact`：仅为允许列表中的 Origin 返回 CORS 预检响应。
- 成功：`200 { "ok": true, "requestId": "..." }`。失败：`{ "ok": false, "error": { "code": "...", "message": "..." }, "requestId": "..." }`。
- `from`、`to` 和 Resend API key 仅来自 Worker 环境；`workEmail` 只映射为 `reply_to`。日志只记录请求标识、事件、结果、状态码和耗时，不记录表单正文、邮箱、电话或 Token。

## 6. 边界场景

- 缺失/损坏图片或视频。
- 小屏幕、超长中文标题、横竖屏切换。
- 键盘导航、焦点可见性、移动菜单展开与关闭。
- `prefers-reduced-motion` 环境。
- 外部论文链接不可达时，站内介绍仍保留完整上下文。
- 无 JavaScript 时核心信息可读。
- 未获批准的 Logo 或强口径不得因素材存在而自动上线。
- 合作表单必填项为空、工作邮箱格式错误或机构网站格式错误。
- Worker Origin、方法、Content-Type、JSON、请求体大小或字段校验失败。
- Cloudflare 限流拒绝、蜜罐命中、Resend 拒绝或网络超时。
- 同一草稿快速双击、失败后重试，以及用户编辑草稿后再次提交。

## 7. Acceptance Scenarios

- **AS-1** Given 首次访客打开首页，When 首屏完成渲染，Then 可看到“协同世界模型：具身智能时代的新范式”、一段说明、商务合作主操作和产品 Demo 次操作。
- **AS-2** Given 访客进入理论区，When 阅读范式对比与核心机制，Then 能区分单智能体、多智能体并行与协同智能，并能通过键盘操作可展开内容。
- **AS-3** Given 访客进入产品区，When 依次浏览三个产品，Then 能理解空间训练场负责训练、COS 负责决策调度、碎蜂负责执行验证。
- **AS-4** Given 访客评估适用性，When 浏览应用区，Then 能看到四类明确场景及其对应图片和能力说明，且不出现禁用强口径。
- **AS-5** Given 访客评估可信度，When 浏览首页合作证据和 About，Then 能看到文档明确的合作与公司信息，不出现 PPT-only 融资数据。
- **AS-6** Given 访客使用桌面或移动导航，When 在首页、About 与联系入口间跳转，Then 每个目标可达、当前状态可理解且无死链。
- **AS-7** Given 视频无法播放或用户暂停视频，When 查看产品媒体，Then poster 和文字仍能完整说明产品，且控制按钮状态正确。
- **AS-8** Given 用户使用小屏、键盘或减弱动态设置，When 完成核心浏览路径，Then 内容不溢出、焦点可见、菜单可关闭、关键内容不依赖动画。
- **AS-9** Given 用户遗漏任一必填项，或输入无效邮箱/网址，When 点击“提交合作需求”，Then 页面阻止后续动作、标记无效字段、聚焦第一个无效字段并在状态区提示修正。
- **AS-10** Given 用户已填写表单，When 在同一标签页刷新页面，Then 所有可见字段及当前 `submissionId` 被恢复、隐藏蜜罐保持为空；Given 字段有效并点击“提交合作需求”，Then 页面仅发起一个请求、禁用提交按钮并在 `role="status"` 中宣布提交中状态。
- **AS-11** Given 请求来自允许的 GitHub Pages 或正式域名且字段有效，When Worker 接收请求，Then 它以环境配置固定发件人和收件人、以访客工作邮箱为 Reply-To 调用 Resend；非允许 Origin、无效字段或超大请求不会调用 Resend。
- **AS-12** Given Resend 接受请求，When 前端收到成功响应，Then 显示“合作需求已提交”并清空草稿，但不声称邮件已经送达；Given 网络或上游失败，Then 保留草稿、恢复按钮并显示可重试与扫码联系提示。
- **AS-13** Given 用户双击或对同一草稿重试，When 多个等价提交到达系统，Then 前端提交锁与 Resend `Idempotency-Key` 防止重复邮件；超出平台限额时返回 429 和明确的稍后重试提示。

## 8. 非目标确认

- 不建设 CMS、数据库、管理后台、账号、在线购买、附件、营销自动化或完整英文站；Worker 只承担合作需求校验与单封事务邮件发送。
- 不新增融资、估值、收入预测、竞品对比、路线图或未经批准的指标。
- 不把所有素材库 Logo 解释为客户或合作关系。
- 不在本次建设三项产品的独立详情页；Section 3 是统一产品入口。

## Design Plan

1. **变更目标**：把旧单页的“产品优先”结构改为“品类—机制—产品—场景—证据—联系”，新增 About 阅读页面，并让联系区承载字段完整的合作需求表单。
2. **影响域**：接口层为 `index.html`、`about.html`；共享视觉和行为位于 `styles.css`、`site.js`，联系提交协调器独立为 `contact-form.mjs`；Worker 代码位于 `worker/`，通过 Resend 外部边界发送邮件，不引入数据库。
3. **放置位置**：页面保留各自内容；导航、菜单、视频控制和视觉 token 共享。静态站规模不足以引入组件框架或构建系统。
4. **依赖方向**：HTML 依赖共享 CSS/JS 和本地资产；联系提交协调器依赖 Worker 的稳定 JSON 契约；Worker 的接口层完成边界校验后调用 Resend，核心校验与邮件投影不依赖平台 SDK。
5. **模型边界**：浏览器请求 DTO、会话级草稿、Worker 规范化后的合作需求和 Resend 邮件 DTO 显式转换；没有服务端 storage model。Markdown 与源文档定义内容边界，HTML 只做公开投影。
6. **替代方案**：继续单文件内联 CSS/JS，改动更少但会在三个页面重复样式与行为，放弃；引入 React/Vite 会增加当前不需要的构建依赖，也放弃。
7. **验证方式**：Node 静态检查、前端真实提交监听器测试、Worker API 单元/集成测试、Wrangler dry-run、本地 HTTP 桌面/移动浏览，以及部署后健康检查与真实收信验收。
